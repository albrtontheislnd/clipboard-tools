# Image Processing Module

## Purpose

The Image Processing module handles all image conversion, compression, and storage operations for the Alapaki Tools plugin. It supports converting clipboard images (PNG) into various web-optimized formats — WEBP, JPEG, PNG, and AVIF — and persisting them either locally in the Obsidian vault or remotely via S3. This is the primary pipeline triggered when a user pastes an image from the clipboard into their notes.

## Scope

- Converting clipboard images (MIME type `image/png` only) to target formats.
- Saving images to the local Obsidian vault (`vault.createBinary`) as binary files.
- Uploading images to an S3 bucket via the API server.
- Server-assisted format conversion (required for AVIF; optional for local/S3 saves).
- Global operation locking to prevent concurrent clipboard processing.
- File naming and path generation via the vault name slug and relative file path.

## Architecture / Flow

The entry point is `handleClipboardImage` in `src/main.ts`, which calls `convertWrapper`. The `convertWrapper` method implements a decision tree with **4 branches** determined by two orthogonal choices:

1. **Conversion location**: local (browser canvas) vs. server (API `/images/transform_download` or `/images/transform_save_s3`)
2. **Save destination**: local vault vs. S3 bucket

```
handleClipboardImage(blob)
  └─ convertWrapper(blob, format, quality)
       ├── Native Local ── canvas.toBlob → vault.createBinary
       ├── Native + S3  ── canvas.toBlob → POST /images/save_s3
       ├── Server Local ── POST /images/transform_download → binary → vault.createBinary
       └── Server + S3  ── POST /images/transform_save_s3 → JSON response
```

### Conversion Location Decision

| Factor | Local (canvas) | Server (API) |
|---|---|---|
| **AVIF format** | Not supported | Required |
| **Native format** (WEBP, JPEG, PNG) | Default (uses web worker with fallback to main thread) | Only if S3 is enabled **and** settings force server path |
| **Settings toggle** | — | `settings.useApiForConversion` |

### Save Destination Decision

| Factor | Local Vault | S3 |
|---|---|---|
| **Settings toggle** | Default | `settings.uploadS3Toggle` |

### Locking

A single global boolean flag (`this.locked`) gates all operations. While `locked` is `true`, any subsequent clipboard paste is ignored. The lock is acquired at the start of `convertWrapper` and released in the `finally` block of a try/catch/finally, ensuring it is always cleaned up even on error.

### S3 Path Construction

S3 object keys follow the pattern:

```
${slugifyVaultName(vault)}/${localPathToPartialUrl(path)}/${randomFilename(ext)}
```

- `slugifyVaultName` normalises the vault name (lowercase, hyphens, no special chars).
- `localPathToPartialUrl` converts the note's local path into a URL-friendly segment.
- `randomFilename` generates a unique filename with the target extension.

## API Endpoints

### `POST /images/save_s3`

- **When called**: Native (canvas) conversion + S3 destination.
- **Payload**: `FormData` with the converted image blob.
- **Response**: JSON containing the S3 object key or URL.

### `POST /images/transform_download`

- **When called**: Server-side conversion, save locally.
- **Payload**: Original clipboard blob + target format + quality.
- **Response**: Binary image data (streamed/downloaded).
- **Usage**: The binary response is saved directly to the vault via `vault.createBinary`.

### `POST /images/transform_save_s3`

- **When called**: Server-side conversion, save to S3.
- **Payload**: Original clipboard blob + target format + quality.
- **Response**: JSON with S3 metadata (object key, URL).

## Conventions

- **Accept only `image/png`**: `handleClipboardImage` checks MIME type and rejects anything else.
- **Default format**: `'avif'` — the plugin prioritises AVIF for best compression.
- **Default quality**: `70` (compression quality scale, 0–100).
- **Single global lock**: `this.locked` boolean — no concurrent clipboard processing allowed.
- **Random filenames**: Generated by `tUtils.randomFilename(ext)` — never uses the original clipboard filename.
- **Unique S3 keys**: Path includes vault slug, note relative path, and random filename.
- **Error handling**: Lock is always released in `finally`; errors are caught and surfaced via Obsidian's `Notice` or console.

## Common Mistakes

1. **Forgetting the lock is global**: All `convertWrapper` calls share the same `this.locked` flag. Calling it from a non-clipboard context can accidentally block clipboard pastes.
2. **AVIF not working**: If `settings.apiServer` is not configured, AVIF conversion silently fails. The UI should warn users that AVIF requires the API server.
3. **S3 without API server**: Enabling `uploadS3Toggle` without a valid `settings.apiServer` will cause upload failures. Validate both settings before entering the S3 branch.
4. **MIME type gate**: Only `image/png` is accepted. Pasted images from non-standard sources (e.g., some browser copies of JPEG) may be silently ignored.
5. **Canvas cross-origin taint**: `convertImageLocally` uses `canvas.drawImage`. If the blob originates from a cross-origin source, the canvas becomes "tainted" and `toBlob` will throw. Always ensure blobs are same-origin or use `{ crossOrigin: 'anonymous' }`.
6. **Path assumptions**: `localPathToPartialUrl` assumes the note path is relative to the vault root. If the active file is `undefined`, the path segment will be missing.
